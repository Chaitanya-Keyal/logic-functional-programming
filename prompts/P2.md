## Prompt 1: apply_op/4, one operator step with exact division

~~~~text
Use the prolog-dev skill for this whole session.

We are starting problem P2 of CS F301 Assignment 2. The solution file is `code/3_q2.pl` (it does not exist yet). The rules for expressions in this problem:

- An expression is a single number, or two expressions joined by one of + - * /, optionally in parentheses. There is no unary minus, and digits of different numbers are never joined into a bigger number. Values of sub-expressions may be negative (for example 3-5).
- Division is allowed only when it is exact (the result is an integer with no remainder) and the divisor is not zero. This applies to every division inside an expression, not just the last.

We will represent an expression tree as either a non-negative integer (a leaf) or a term `bin(Op, Left, Right)` where Op is one of the atoms `+`, `-`, `*`, `/` and Left and Right are expression trees.

Task for this prompt only: create `code/3_q2.pl` with one predicate, `apply_op(?Op, +A, +B, -Value)`, which relates an operator to the integer result of applying it to the integers A and B:
- Op is one of `+`, `-`, `*`, `/`; when Op is unbound, apply_op enumerates the four operators on backtracking.
- For `/` it fails (never throws) when B is 0 or when A is not divisible by B; otherwise Value is the exact integer quotient, which must also be right when A or B is negative.
- Value is always an integer, never a float or a rational.

File rules: no assert, retract or global variables, no initialization directive, no halt, only the libraries lists, apply, yall and aggregate, nothing printed, and the file loads silently. Do not write any other predicate yet.

Then test it on cases including 7/2 (fails), 6/0 (fails), 0/5, -6/3, 6/(-3), -7/2 (fails), and the enumeration of all four operators for A = 6, B = 3, and report the results.
~~~~

**Outcome:** Kept as written. We re-ran the division edge cases: 7/2, 6/0 and -7/2 fail without an exception, -6/3 and 6/-3 give -2, and the four operators enumerate for an unbound Op.

## Prompt 3: expression_string/2, the canonical printer

~~~~text
Follow the prolog-dev skill.

Next unit for P2: the predicate `expression_string(+Tree, -String)`, which converts an expression tree to its canonical text. The result is an SWI-Prolog string (not an atom, not a code list) with no spaces. Numbers are written in decimal. Parentheses are printed by this rule, which gives every different expression tree a different string:

- * and / bind tighter than + and -.
- Operators are left-associative.
- A left operand is written in parentheses only if its top operator has lower precedence than its parent's.
- A right operand is written in parentheses if its top operator has the same or lower precedence than its parent's.
- A single number is never in parentheses.

Examples of the rule: (4+2)*3, 4+2*3, 8/4*2 (this is (8/4)*2), 8/(4*2), 1-2-3 (this is (1-2)-3), 1-(2-3), 1+(2+3), 1+2+3 (this is (1+2)+3). Note that 1+(2+3) and 1+2+3 are different trees.

Do not build the string from a term with term_to_atom/2 or similar; walk the tree. Do not change the existing predicates and do not write any other predicate yet.

Then check all eight examples above (build each tree by hand and compare the result with `==` against the expected string), check that `string/1` holds for the results, and check that all the trees expression/3 produces for [1,2,3,4] give pairwise different strings. Report the results.
~~~~

**Outcome:** Kept as written. We checked the parenthesis conditions against the rule (left operand only when its operator binds less tightly, right operand when it binds equally or less tightly) and re-ran the eight examples; all 153 trees for [1,2,3,4] print to distinct strings.

## Prompt 4: equation/2, the relation between a list and its valid equations

~~~~text
Follow the prolog-dev skill.

Next unit for P2: the predicate `equation(+List, -Equation)`, the core relation that the task predicates will use. The problem: given a list of non-negative integers, insert the operators +, -, *, / and exactly one = between the numbers (using every number once, in the given order, with optional parentheses) so that both sides of the equation have the same value.

- Let the list be n1, n2, ..., nk. An equation is L=R, where L is an expression over n1..nj and R is an expression over n(j+1)..nk, for some j with 1 <= j < k. Every number is used exactly once, in order.
- Both sides must have the same integer value.
- Equation is the canonical string of the equation: the canonical string of L, then "=", then the canonical string of R, as an SWI-Prolog string with no spaces, for example "4*2=5+3".

Declarative reading: Equation is the canonical string of a valid equation for List. On backtracking it yields every valid equation. It fails for lists of length 0 or 1 and when no valid equation exists, and it always terminates. Build strings only for pairs of sides whose values are equal, and never build a string and parse it back to evaluate it. Use expression/3 and expression_string/2; do not change them and do not write any other predicate yet.

Then report all answers for [4,2,5,3] (expected, in some order: "4*2-5=3", "4*2=5+3", "4-2=5-3", "4/2=5-3", "4=2*(5-3)", "4=2+(5-3)", "4=2+5-3"), for [2,4,8] (expected only "2*4=8"), and check that [2,3,4], [] and [7] give no answers.
~~~~

**Outcome:** Kept as written. All seven [4,2,5,3] equations and the single [2,4,8] equation from the handout appear; [2,3,4], [] and [7] give none; [1,2,3,4] matches our own enumerator.
